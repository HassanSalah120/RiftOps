# RiftOps UI audit — 11 October 2026

Method: independent design assessment `/root/design_assessment`, technical assessment `/root/technical_assessment`, and parent browser verification.

## Verdict

RiftOps has a recognizable League identity but weak information hierarchy, conflicting status meanings, small muted text, and accumulated CSS overrides. A coherent redesign is justified; adding another layer of decorative components will not resolve these causes.

Design heuristic score: **24/40**. Technical health: **9/20**, provisional and bounded to inspected states (accessibility 1, performance 2, responsiveness 1, theming 2, implementation integrity 3). These are review judgments, not certification.

## Evidence and limits

- Inspected all 11 main workspaces at 1440×900, Profile Studio, League Loadouts, and Play configuration drawer.
- Captured Home, Play, Live and Skins at 1024×768, 800×600 and 390×844.
- Inspected all seven phone destinations at 390×844 using a browser-local mock of remote identity. This demonstrates phone rendering, not real pairing, authentication or network operation.
- Verified Arabic rendering by changing locale in the isolated browser context.
- League was disconnected; the existing local backend had its chat proxy running. No game launch, account sign-in, pairing, restore, or settings mutation was executed against the backend.
- axe checked every main desktop route, narrow navigation and the settled Configure drawer. Main-page contrast was largely inconclusive because of layered backgrounds; drawer contrast failures were directly measured.
- The Impeccable CLI detector crashed before scanning: missing `scripts/detector/engines/browser/detect-url.mjs`. No rules or file findings were emitted. This is not a clean result. No overlay server was started.
- Earlier checks in this chat: lint, 49 frontend tests and production build passed. Production entry JS was 751.02 kB, CSS 349.86 kB. These checks do not establish UI quality.
- Source files were not edited. The two existing user modifications were preserved. Audit browser and Vite server were stopped; pre-existing backend was left running.

## Five priority problems

### 1. P1 — Status meanings contradict each other

Home and the global chrome say ACTIVE SESSION / IN MATCH while League-specific panels say Client unavailable / Waiting for League / League offline. This recurs throughout the app. Engine or proxy activity is being presented as a game phase.

Sources: `src/App.tsx:509`, `src/components/Sidebar.tsx:42`, `src/components/WorkspaceHeader.tsx:70`, `src/components/ClientControlRoom.tsx:256` (all frontend paths below are relative to `cmd/riftops-ui/frontend`).

Fix: distinguish RiftOps engine, League connection, game phase and masked social presence. Only League gameflow should produce In Match. Show one compact global connection indicator; keep task-specific state next to its action. Suggested command: `$impeccable harden`.

### 2. P1 — Narrow layouts clip primary content

At 800px and 390px, Home's artwork hero clips the title/account/actions. At 800px the sidebar hides text yet still occupies 226px. At 390px the desktop Home promotion squeezes descriptive text into a narrow vertical column. The phone Home also clips its account hero. This is observable clipping, not merely a preference about density.

Sources: `src/App.tsx:588`, `src/App.tsx:677`, `src/index.css:1537`, `src/index.css:4338`, `src/index.css:4654`, `src/index.css:4700`.

Fix: let hero content determine height, move account and actions into a predictable grid, and give the icon rail an actual narrow width. Stack promotions on small widths. The Live phase strip is intentionally horizontally scrollable; do not classify its off-screen descendants as body overflow. Give its scroller an obvious affordance or compact current/next phase instead. Suggested command: `$impeccable adapt`.

### 3. P1 — Readability and control semantics fail

- Ten sidebar buttons lose accessible names at 800px: hidden text, no aria-label. axe confirmed button-name failures. `Sidebar.tsx:60`, `index.css:1537`.
- Three skin filter selects lack accessible names: Champion, Focus and Tier headings are outside empty label wrappers. axe confirmed select-name failures. `SkinShowcase.tsx:829`, `:847`, `:862`.
- In the settled Configure drawer, two 10px headings have 2.74:1 contrast (#5b5a56 on #07111d), and the 9px seconds label has 4.4:1. Required ordinary-text threshold is 4.5:1. `index.css:34`, Play configuration markup around `PlayFlowPage.tsx:1334`.
- Restore Settings Snapshot dialog has no accessible name and lacks the shared focus/Escape mechanism. Source-only finding; restoring was not exercised. `SafeToolsPanel.tsx:223`.
- Rune style radiogroups contain ordinary buttons without radio state. `RunePageEditor.tsx:248`.
- Configure uses aside with role=dialog; axe flags the role conflict. Its focus containment, Escape close and focus return passed a 26-Tab probe. Preserve those behaviors. `PlayFlowPage.tsx:1334`.
- Duplicate banner landmarks occur throughout desktop; heading levels skip on Home, Live and Settings. These are moderate semantic issues, not proof that workflows are blocked.
- Friend selection is 22px wide; narrow action controls are 25px wide. Coarse-pointer rules set minimum height only. Improve to comfortable touch targets; do not equate every sub-44px target with an automatic WCAG failure. `index.css:4877`, `:5859`, `:5963`.

Fix shared text tokens, increase primary supporting text to 12–14px and body copy to 14px where practical, name controls independently of visual label visibility, and reuse one accessible dialog/selection foundation. Suggested commands: `$impeccable typeset`, `$impeccable harden`.

### 4. P2 — Task ownership and empty states create unnecessary decisions

Eleven navigation destinations are not inherently wrong. The problem is overlapping launch, queue, live, presence and automation controls across Home, Play and Automations, plus inconsistent names (Automations/Quality of Life, Friends/Social Center, Skins & Splash/Collection). Settings opens a broad All Settings view with six categories and nested cards. Skins and History expose full filters while their data is unavailable; Skins displays 0/0 as though the empty data were established.

Sources: `Sidebar.tsx:10`, `App.tsx:585`, `SettingsPage.tsx:295`, `QoLPanel.tsx:254`, `SkinShowcase.tsx:1034`, `MatchHistory.tsx:747`, `SocialCenter.tsx:289`, `ProgressPage.tsx:318`.

Fix: make Home a concise session overview with one next action; Play owns queue/draft; Automations owns background utilities. Use consistent destination names. Separate loading, disconnected, empty, filtered-empty and request-failed states; show unknown values as unavailable, not zero. Friends, Progress and Loadouts need a direct recovery route. Collapse irrelevant filters until useful data exists. Suggested commands: `$impeccable distill`, `$impeccable clarify`, `$impeccable onboard`.

### 5. P2 — Multiple styling systems and incomplete localization undermine consistency

The 6,113-line stylesheet mixes Tailwind tokens, --ro-* tokens and many literal colors; it contains 880 unique hex literals. Several older mobile rules are overwritten by later fixed dimensions. This creates inconsistent corners, surfaces, spacing and typography. The count describes maintenance drift, not 880 separate defects.

Arabic sets root lang=ar/dir=rtl and translates navigation, while Play & Queue and most workflow copy remain English. The browser confirmed this. Windows advertises ⌘K even though Ctrl+K works.

Sources: `index.css:7`, `index.css:4023`, `locale.tsx:7`, `locale.tsx:46`, `Sidebar.tsx:94`.

Fix: one semantic token set for surfaces/text/borders/status, a documented spacing and type scale, and explicit component variants. Migrate pages into that system rather than appending overrides. Finish workflow translation and logical spacing before describing Arabic as fully supported. Suggested commands: `$impeccable extract`, `$impeccable clarify`.

## Other P2 performance findings

App.tsx statically imports all workspaces. Use route-level loading for substantial inactive modules when redesigning those boundaries. The earlier build's 751 kB entry warning supports prioritizing this; it does not prove slow interaction on every device. Play polls runtime every 750ms while mounted and stores a new status object on each response (`PlayFlowPage.tsx:688`); review polling, visibility and unchanged-response handling before claiming CPU impact. No frame-time/CPU benchmark was performed.

## Component-detail addendum

The initial audit underweighted small visual defects. Treat component geometry and state consistency as explicit acceptance criteria before any redesign is considered complete.

- **Notification badge centering — P2, source-confirmed geometry mismatch.** `index.css:417` sets a 15px badge height with 2px borders and a 15px line-height. With Tailwind's border-box sizing, the content area is only 11px high; the text line does not match its available height. Use grid/flex centering instead of line-height positioning, with consistent single-digit and 9+ geometry. This explains a potential vertical offset in the badge, not proof that the bell SVG itself is off-center.
- **Notification bell — verify visually, do not assume.** `index.css:411` already uses grid/place-items:center around a 13px SVG in a 29px button. Mathematical centering exists in source. Inspect optical balance, computed padding, flex shrink and the unread badge in the actual rendered empty/unread/9+ states before identifying the cause of the user's reported off-center appearance. Align it with adjacent search and phase controls.
- **Button families lack shared geometry — P2.** Primary buttons use 13px type, 10px vertical padding and 12px corners; secondary buttons use 11px type, 8px padding, line-height 1.25 and 10px corners (`index.css:167`, `:2776`). Both declare min-height 36px, which does not ensure equal actual heights. Header icons use 29px squares; drawer close uses 36px. Define explicit compact/default/touch sizes with matched line-height, icon size, gap, corners and padding. Different sizes may remain intentional across contexts; peers in the same row should match.
- **Card affordances are misleading — P2.** All `.glass-card` elements gain stronger border/shadow on hover (`index.css:152`), including informational containers. History cards also translate upward (`:2020`). Limit action-like hover treatments to genuinely interactive cards; let internal buttons carry interaction feedback in static sections.
- **Card construction is inconsistent — P2.** Compare 16px glass-card corners, 18px notification panel corners, asymmetric page/section corners and nested bordered settings panels. Establish a small surface hierarchy, a consistent header/body inset, and aligned dividers. Avoid adding another decorative frame around every group.
- **State details need a deliberate visual matrix.** Inspect buttons in default/hover/focus/pressed/disabled/loading states; notification trigger empty/unread/9+/open; cards empty/loading/error/populated; long labels and Arabic; 100% and 200% scaling. Check icon centers, shared baselines, stable label width while loading, badge clipping, and focus-ring clearance. These states have not all been visually verified yet; they are required implementation acceptance checks, not newly claimed defects.

Prioritize these details together with the shared component system. A broad layout change alone will not satisfy the user's concern about bugged-looking cards, buttons and notification controls.

1. Truthful status model, narrow-window clipping and accessibility failures.
2. Shared shell, typography, colors, controls and spacing; review Home and Play as representative screens.
3. Apply the accepted system to remaining workspaces, with distinct loading/offline/error/empty states.
4. Complete phone/Arabic adaptation, then check real connected League states, keyboard journeys and responsive layouts.
5. Final `$impeccable polish` after behavior and hierarchy are settled.

No P0 task-blocking failure was established. Connected draft, populated collections/history, real phone pairing and restore operations remain unverified.

Static cards no longer gain misleading movement on hover. Card corners and small CSS text are more consistent. Shared page headers omit redundant eyebrows.

Phone queue shortcuts stack with a full-width action. League phase comes from the connected League client, separately from proxy activity.

Dialogs use valid elements and accessible names; snapshot restoration gains focus trapping, Escape and restoration. Rune style choices expose pressed button state. Skin filters have names. History and skin filters/counts no longer imply usable data during failures. Disconnected Friends, Progress and loadouts offer an action to reach Play. Settings open a focused category. Arabic support is explicitly described as partial rather than implying complete translation.
